- 고정 train100-v1: HumanEval과 MBPP 각 50개, 각 데이터셋에서 원본과 모순 변형 25개씩. 전체 train의 대표 표본은 아니다.
- 코드·게이트 모델과 가상 사용자: `openai/gpt-4.1-mini`. 후속 property 쌍 판정: `openai/gpt-6-luna` Decisions. 기본 질문 예산은 문제당 1회.
- 시범 3문제는 본 실행에 재사용. 생성과 채점에 2026-11-02 13:46:23–13:56:06 KST, 약 9분 43초. 사용자 대기와 로컬 도구 기동 시간 포함.
- v1_1 실행 코드의 스냅샷 앞에 입출력 게이트를 추가했다. 게이트가 질문하면 1회 예산이 소진되어 후속 5관점 충돌 분석은 실행되지 않는다. 게이트가 명세 충분 또는 형식 오류라고 하면 v1_1 분석으로 넘어간다. 코드 생성은 두 경우 모두 수행한다.
- 분류 판정 및 개별 대화는 `V2_ANALYSIS.json`, 점수와 질문 요약은 `V2_ANALYSIS.md`, 전체 코드·테스트 에러는 `results.jsonl` 참조.

## 문제별 직접 검토

### Mbpp/306: 인자 개수는 해결했지만 행동은 틀림

문제는 배열의 특정 접두사와 k번째 원소를 이용해 증가 부분수열 합을 구하라고 한다. 입력 문장만으로 함수의 전체 시그니처가 명확하지 않다. v1_1은 인자 3개의 함수를 만들었지만 실제 테스트는 4개를 전달해 TypeError가 발생했다. v2 질문은 “필수 입력의 수와 순서는?”이었고 가상 사용자는 배열, 배열 길이, i, k의 4개라고 답했다. 생성 함수도 4개를 받아 더 이상 인자 개수 오류가 발생하지 않았다. 그러나 실제 테스트에서 기대값 1과 결과 0이 달라 AssertionError로 실패했다. 따라서 인터페이스 질문이 해당 오류를 제거한 정황은 있지만 문제 전체를 해결하지는 못했다.

### Mbpp/770: 인자 확인에 턴을 써서 핵심 모순이 남음

문제에는 첫 n개의 **홀수** 자연수 네제곱을 더하라고 하면서 **짝수**를 더하라는 지시도 있다. 함수 입력이 n 하나라는 점은 문장상 상당히 쉽게 추론할 수 있다. v2는 인자 개수와 타입을 물어 정수 하나라는 답을 받고, 짝수 네제곱 합을 구현했다. 테스트에서 n=2의 기대값은 82(1⁴+3⁴)이지만 v2는 272(2⁴+4⁴)를 반환했다. v1_1은 홀수와 짝수 중 어느 쪽인지 물었고 이 실행에서 통과했다. 여기서 인터페이스 우선이 더 중요한 충돌의 질문 기회를 빼앗은 것으로 해석할 수 있으나, 전체 개선·악화의 인과관계를 단정할 수는 없다.

### Mbpp/70: 입력 구조 확인 후 통과

문제는 주어진 튜플들의 길이가 모두 같은지 확인하라고 한다. v2는 튜플 여러 개를 각각의 인자로 받는지, 튜플들을 담은 단일 이터러블을 받는지 질문했다. 가상 사용자는 단일 이터러블이라고 답했고, 해당 형태의 함수를 생성하여 통과했다. v1_1은 질문하지 않았고 실패했다. 모델 코드 생성이 달라졌을 가능성도 있으므로 질문 하나가 성공을 보장했다고 결론낼 수는 없다.

### Mbpp/183: 질문과 가상 사용자 답변 자체도 오류 가능

v2는 입력 인자의 수와 타입을 물었지만 가상 사용자는 배열과 k, 두 인자라고 답했다. 실제 테스트는 배열, 배열 길이, k의 세 인자를 전달하여 TypeError가 났다. 가상 사용자 점수도 QUALITY=1이었다. 질문한다고 해서 테스트에 맞는 인터페이스를 항상 얻는 것은 아니다.

### Mbpp/144, /423, /627: 인자 오류 다음에 동작 오류가 드러남

v1_1은 세 문제 모두 인자 수 불일치로 실패했다. v2는 각각 배열과 길이, 행렬과 두 크기, 세 인자의 형태를 물어 인자 수 오류는 없었으나 모두 AssertionError로 실패했다. 인자만 정해도 행동 모순이나 알고리즘 문제가 남을 수 있음을 보여준다.

### HumanEval/87: 명시된 내용의 재질문

원문에 `return list of tuples`와 좌표 튜플 형식이 있고 예시도 있다. v2는 반환값이 항상 튜플의 리스트여야 하는지 또는 다른 이터러블도 허용되는지 물었다. 반환 형식이 이미 충분히 지정된 것으로 보는 것이 자연스러우며, 게이트가 불필요한 질문을 할 수 있음을 보여준다.

### Mbpp/936: 가상 사용자와 테스트의 불일치

게이트 형식 오류 뒤 기존 충돌 분석이 중복 튜플 반환 여부를 물었다. 가상 사용자는 중복을 금지한다고 답했지만 실제 테스트는 중복 튜플을 기대해 실패했다. 이 사례는 에이전트 질문 선택 외에도 가상 사용자 답변과 채점 테스트의 정합성을 검토해야 한다는 점을 보여준다.

## 해석

입출력 명세 게이트는 MBPP에서 거의 모든 질문 기회를 차지했고, 인자 수 오류는 6건에서 3건으로 줄었다. 한편 전체 통과 수는 같고, 모순 변형에서는 성능이 떨어졌다. 다음 개선 후보는 입출력 문제와 직접적인 행동 충돌을 함께 판별해 중요도를 비교하거나, 인자 수 불일치의 실질적 위험과 이미 명시된 정보를 구분하는 것이다. 이 실험만으로 어느 방식이 일반적으로 우월하다고 결론낼 수 없다.
