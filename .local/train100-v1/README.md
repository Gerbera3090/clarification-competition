# 고정 train 100문제: train100-v1

두 알고리즘에 정확히 같은 문제와 가상 사용자용 참조 설명을 제공하기 위한 실험용 표본이다.

- 원본 문제 ID 100개, 각 ID에서 하나의 문제 변형.
- HumanEval 원본, HumanEval 모순 변형, MBPP 원본, MBPP 모순 변형 각각 25개.
- train split에 속하고 비어 있지 않은 `reference_prompt`가 있는 문제만 선택했다.
- 난수 시드는 `20261030`이다. 균형 표본이므로 전체 train 분포의 무작위 대표 표본은 아니다.
- `reference_prompt`가 있다는 것만으로 가상 사용자 답변과 테스트 기대값의 일치는 보장되지 않는다.
- 모순 변형 파일이라는 출처는 실제 모순 유무에 대한 독립 정답 라벨이 아니다.

`manifest.json`에는 문제 ID, 출처, 문제와 참조 설명의 SHA-256 및 배치 해시가 있다. `batches/`에는 SDK 실행용 입력이 있다. 입력 파일에는 평가 환경에서 사용하는 참조 정보도 포함되지만, 참가 알고리즘에는 SDK가 `prompt`와 `entry_point`만 제공한다. 알고리즘이 직접 참조 정보나 테스트를 읽어서는 안 된다.

`algorithms/`는 이번 실험에 사용한 코드 사본이고 `algorithm-snapshots.json`에 해시가 있다. `pbt2/`, `pbt3/`에 배치별 응답과 실행 로그를 저장한다. 응답 생성기는 입력과 코드의 해시를 확인하고 기존 배치 결과를 덮어쓰지 않는다.

PBTClarifier3의 첫 시도에서 모델이 원문 인용에 바깥 따옴표를 덧붙여 인용 검증이 실패했다. 원문과 동일한지 확인하는 검증은 유지하면서 바깥 따옴표를 허용하도록 수정하고, 공정한 비교를 위해 PBTClarifier3의 100개를 처음부터 다시 실행했다. 첫 시도 기록은 `pbt3-first-attempt/`에 별도로 보존한다. 해당 시도의 모델 사용량은 재실행 결과의 비용 합계 밖에 있다.

PBTClarifier2의 78번째 문제에서 실행이 오랫동안 응답 없이 멈춰 중단했다. 완료된 77개는 보존하고, `recovery/`의 미완료 3개와 이후 두 배치만 재개했다. 재개 구간은 LiteLLM 요청 제한 시간을 90초로 설정했다. 중단된 호출의 청구액은 완료된 결과의 비용 합계에서 확인할 수 없다.

실험 중 SDK의 `clarify/llm.py`에 작업 트리 변경이 있었다. 변경된 부분은 Ollama 모델에만 적용되며, 이번 OpenAI 모델 호출에는 해당하지 않는다. 실행 후 확인한 변경 내용과 해시는 `sdk-working-diff.patch`, `sdk-state.json`에 기록했다.

이 실험은 train 개발용 표본이다. 최종 제출 및 성능 보고에는 대회 규칙에 맞는 별도의 validation 평가가 필요하다.
