# SpecTrace 전체 실험 해석

## 설정과 결과

- 고정 train100-v1: HumanEval/MBPP, 원본/모순 변형을 각각 25개씩 선택했다.
- 모델: 코드 생성, 요구 분석, 가상 사용자 모두 GPT-4.1 mini. 최대 질문 1회.
- 통과 47/100, TDS 0.4648, 질문 42/100, 완료 응답 기록 모델 비용 $0.185909.
- 초기 파일럿 및 중단 호출 비용은 이 비용에 포함되지 않는다.
- 완료된 로그에서 일반 모델 호출 336회, 가상 사용자 질문 42회를 확인했다. 중단된 시도는 제외한다.
- 추적은 LLM이 내놓은 설명이다. 프로그램 실행이나 정형 증명을 통한 충돌 검증은 아니다.

## 눈여겨볼 사례

- HumanEval/33: 반환 타입에 대한 요구가 리스트와 정수로 충돌한다고 추론하고 하나의 질문을 했다. 가상 사용자는 리스트라고 답했고 생성 코드는 통과했다.
- HumanEval/107: 모델이 범위와 예시 사이에 충돌 후보를 만들었지만, 독립 확인 단계가 결과가 일치한다고 판단하여 기각했다. 해당 코드는 통과했다.
- Mbpp/461: 대문자를 세라는 요구와 대문자를 무시하라는 요구의 충돌 후보를 확인했다. 확인 모델은 설명에서는 충돌이 맞다고 하면서 JSON의 `confirmed`에는 `false`를 반환했다. 알고리즘은 이 값을 따라 질문하지 않았고 코드 테스트는 실패했다. 설명과 구조화된 판단이 모순되는 사례다.

## 비교 기준

기존 결과는 함수 이름 대소문자 처리 수정 이후 고정된 100문제 중 영향이 있는 3문제를 다시 채점한 결과다. 이전에 보고한 점수와 일부 다르다. 같은 채점 기준 표는 `../current-runtime-review/COMPARISON-current-runtime.md`를 참고한다.

원본/모순 변형 그룹은 구성 목적을 나타내며, 개별 충돌 검출의 정답 라벨로 취급하지 않는다. 1회 확률적 실행이므로 우열이나 질문의 인과 효과를 확정할 수 없다.
