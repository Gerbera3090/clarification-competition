# v1과 v1_1 — 문제·질문·결과 직접 분석

## 검토의 범위

- 기존 고정 train100-v1의 사용자에게 제시된 prompt 100개를 하나씩 읽고 우선 확인할 쟁점, 근거, 제안 질문을 적었다.
- 이후 v1과 v1_1의 실제 질문, 가상 사용자 답변, 생성 코드와 테스트 실패 로그를 대조했다.
- 단일 검토자의 의견이다. 이전 실험 및 대화를 알고 있어 맹검이 아니며, 원문 의견 5건은 결과를 본 뒤 수정했다. 문제별 표에 표시했다.
- 한 문제에 모순과 모호함이 함께 있을 수 있다. 하나의 우선 쟁점만 적었으므로 범주는 완전한 정답 레이블이 아니다.
- 다른 질문도 정당할 수 있으며, 검토 의견에 따른 분류를 대회 질문 품질의 공식 정답으로 간주하면 안 된다.
- 명세 모순 여부를 평가하기 위해 숨겨진 테스트를 알고리즘에 전달하지 않았다. 사후 실패 분석에서는 train 채점 로그와 원래 reference를 참고했다.

## v1과 v1_1의 비교

| 항목 | v1 | v1_1 |
|---|---:|---:|
| 코드 통과 | 53/100 | 57/100 |
| TDS | 0.5149 | 0.5557 |
| 질문 | 77/100 | 72/100 |
| 기록된 모델 비용(에이전트 + 가상 사용자) | $0.460522 | $0.460588 |
| 완료 문제에서 일반 GPT 응답 호출 | 795 | 794 |
| decision model 호출 | 0 | 95 |

- 짝지은 결과: 모두 통과 50, v1만 통과 3, v1_1만 통과 7, 둘 다 실패 40.
- v1_1의 GPT는 원문에서 속성 407개를 추출했고, 원문 인용이나 필수 필드 검증에 통과하지 못한 43개는 제외했다. 속성이 두 개 미만인 문제 5개는 decision 비교가 없었다.
- 95개 문제의 속성 쌍 785개를 decision model로 분류했다. compatible 747, conflict 30, uncertain 8이다. 이는 모델의 출력이며 정답 라벨이 아니다.
- v1 속성 관점은 99개 정상 판단 중 52개 문제에서 충돌을, v1_1 decision 속성 관점은 95개 판단 중 18개 문제에서 하나 이상의 충돌을 표시했다.
- 속성 추출 내용과 프롬프트, 결과 형식이 함께 달라졌고 출력도 확률적이어서 차이를 decision model의 인과 효과로 단정할 수 없다.
- v1_1에서 속성 추출은 여전히 GPT 호출이다. 그래서 GPT 호출 수는 거의 같고 decision 요청이 추가되었다. 현재 로그는 decision 비용만을 신뢰성 있게 분리하지 못한다.
- v1_1 최종 질문 72개 중 최종 LLM이 속성을 sources로 표기한 것은 4개이며, 이 4개에서는 decision 속성 충돌 판정이 false였다. 충돌이라고 판정한 18개 문제 중 최종 질문의 sources에 properties가 표기된 것은 없다. sources는 최종 모델의 자기보고이므로 실제 영향이 0이라는 증거는 아니다.

## 실제 실패와 관찰

1. HumanEval/21 — 가능한 문제의 불완전 조건: 최소 원소와 최대 원소를 각각 0과 1로 보내라는데 입력이 모두 같을 때 조건이 충돌한다. v1_1은 이 경우를 물었고 가상 사용자는 0 목록이라고 답했다. v1도 v1_1도 테스트는 통과했다. 데이터가 전체가 같은 입력을 실제로 검사했는지는 별도로 확인해야 한다.
2. HumanEval/88 — 후보 코드 버그를 요구사항 문제로 오인: 원문 예시에 빈 입력 결과 "[]"가 있지만 v1_1은 한 후보 코드의 IndexError를 이유로 빈 입력을 처리해야 하는지 질문했다. 코드 오류를 질문으로 바꾼 사례다. 최종 코드도 기준 테스트에서는 실패했다.
3. HumanEval/111 — 핵심 충돌 대신 명시된 조건 재질문: 원문은 최빈 문자만 반환한다고 이미 말하지만 v1_1은 최빈 문자만 반환하는지 물었다. 딕셔너리와 정수 반환 충돌은 묻지 않았고, 최종 코드는 연속 공백을 빈 문자열 토큰으로 세어 실패했다. v1은 타입을 물어 이 테스트를 통과했다.
4. Mbpp/645 — 요구 파악과 가상 사용자 불일치: 곱을 구하라는 요구와 항상 0 반환 요구가 대립한다. v1은 두 선택지 모두 0을 반환한다는 질문을 만들었고 v1_1은 질문하지 않았다. 둘 다 실패했다. v1_1 속성 추출은 '곱은 구하지만 무시하고 0 반환'으로 요구를 한데 합쳐 decision model이 비교할 대립 속성 자체를 보지 못했다.
5. Mbpp/70 — 입력 인터페이스 누락: prompt는 여러 튜플을 어떻게 전달할지 밝히지 않는다. 두 버전은 가변 인자로 구현했지만 테스트는 튜플 목록 하나를 전달해 둘 다 실패했다.
6. Mbpp/763 — 인자 수 불일치: prompt에는 배열만 언급되지만 생성 코드는 인자 하나, 채점 호출은 배열과 길이 두 인자를 사용해 두 버전 모두 TypeError가 났다. 제공된 명세만 보고 추가 인자가 필수임을 단정할 수 없다.
7. Mbpp/461 — 유사한 질문, 다른 가상 사용자 답변: v1 답변은 대문자를 세라고 했고, v1_1 답변은 첫 대문자를 제외하라고 했다. 공개 train의 'PYthon' 테스트는 1을 기대해 v1_1은 통과하고 v1은 실패했다. 이 1건의 차이를 decision model의 충돌 판단 개선 효과라고 단정할 수 없다.
8. Mbpp/874 — 통과가 전체 정합성을 보장하지 않음: v1_1은 예시 ('abab','ab')에 대해 False를 반환하도록 특수 처리했고 테스트를 통과했다. 원래 과제의 일반적인 문자열 반복 판정에서는 이 입력이 참이므로 통과만으로 모든 요구가 해결됐다고 볼 수 없다.
9. Mbpp/753 — 질문했어도 답변과 채점 불일치: v1은 최소·최대 충돌을 묻지 않았고 v1_1은 질문했다. 가상 사용자는 최대 k개를 택했지만 채점은 최소 k개를 기대해 두 실행 모두 실패했다.
10. HumanEval/55 — 질문과 별개인 코드 계산 문제: 피보나치 결과의 문자열·정수 타입 등 요구가 충돌한다. 두 코드가 부동소수점 공식을 써서 71번째 값에서 1 차이가 발생해 실패했다.

## 실패 로그의 형태

- v1 실패 47건: AssertionError 32, TypeError 11, ValueError 4. TypeError 중 인자 개수 불일치 8.
- v1_1 실패 43건: AssertionError 32, TypeError 8, ValueError 3. TypeError 중 인자 개수 불일치 6.
- 이는 첫 번째 실패 로그에 나타난 예외 종류의 분류이지 근본 원인의 정답 분류가 아니다.
- 데이터셋의 원본 reference 및 테스트와 가상 사용자의 답이 실제로 다를 수 있으므로 코드 실패를 질문 품질만으로 환원해서는 안 된다.

## 다음 확인

- 우선 property 추출에서 서로 대립하는 문장을 한 항목으로 뭉개지 않도록 원문 인용을 원자적으로 분리하고, 단일 속성 내부 모순도 검사한다.
- 같은 추출된 속성 목록을 GPT와 decision model 양쪽에 그대로 넣어 판정 결과를 비교해야 모델 선택의 효과를 분리할 수 있다.
- 원본·모순뿐 아니라 별도의 ambiguous·incomplete train 변형을 고정한 표본이 필요하다. 현재 100개 결과는 그 성능을 나타내지 않는다.
