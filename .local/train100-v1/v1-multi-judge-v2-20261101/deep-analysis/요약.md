# v1 질문 출처와 충돌·모호성 분석

## 범위

- 2026-11-01의 v1 실험, 고정 train100-v1 100문제, GPT-4.1 mini, 질문 최대 1회.
- 선별: HumanEval 원본 25개, HumanEval larbi_contradictory 25개, MBPP 원본 25개, MBPP larbi_contradictory 25개.
- 다른 이름의 ambiguous·incomplete 변형은 이 표본에 포함되지 않는다. 원본이 모두 완전하다는 뜻은 아니다.
- 관점들이 공유하는 모델, 원문과 구조화 자료 때문에 독립적인 판정으로 보장되지 않는다.

## 최종 질문 출처

최종 질문 77개에 한정한 `sources` 자기보고: simple 73, structure 또는 structured 30, instruction_example 16, code_comparison 20, properties 21. 한 질문에 복수 관점이 들어갈 수 있다. 모델이 자기보고한 참고 자료이며, 실제 인과적 기여를 입증하지 않는다. 질문이 없는 23개에도 sources가 비어 있지 않을 수 있어 전체 100개 집계와 혼동하지 않는다.

- simple만 표시한 질문 32개.
- property를 출처로 표시한 질문 21개 중 해당 관점이 명시적 충돌이라고 판단한 것은 10개, 충돌이 없다고 판단한 것은 11개. 속성 목록이 누락 정보 질문에 사용될 수 있다.
- 다섯 관점 모두 `has_conflict=true`가 아닌데도 최종 단계가 질문한 문제는 12개. 모두 원본 출처였지만 질문의 실제 필요성을 뜻하지 않는다.
- 두 코드가 예시 입력에서 실행된 49개 중 예외 또는 직렬화 불가 없이 두 코드가 값을 낸 경우는 41개, 그 가운데 관찰 결과가 다른 경우는 24개다. 실행 차이가 원문의 충돌을 증명하지 않는다.

## 표본과 결과

- 원본: 50개, 통과 39개, 질문 29개.
- larbi_contradictory 변형: 50개, 통과 14개, 질문 48개. 질문한 48개 중 14개 통과, 34개 실패. 질문하지 않은 두 개도 실패.
- 이는 데이터 파일 출처에 따른 집계이지, 각 문장의 실제 정답 충돌 여부나 질문의 원인 효과가 아니다.
- 별도로 larbi_ambiguous, larbi_incomplete, akli_under-specification 등 공개 train 변형이 있으나 이번 고정 표본에는 선택하지 않았다. 서로 같은 task_id의 여러 변형이 될 수 있다.

## 읽어볼 사례

- HumanEval/33: 다섯 관점이 리스트/정수 충돌을 지적. 최종 모델은 다섯 출처를 표기하며 반환 타입을 물었고 코드 통과.
- HumanEval/55: 다수 후보 중 instruction_example만 출처로 표기해 입력 타입에 따른 반환 타입을 질문. 답변은 얻었지만 생성한 부동소수점 피보나치 코드가 71에서 1 차이로 실패.
- Mbpp/18: property 관점은 충돌 없음이라고 했지만 대소문자 관련 가정을 제안. 최종 질문은 대소문자 구분 여부를 물었고 출처는 properties만 표기. 코드 통과.
- Mbpp/645: simple 후보는 실제 곱과 0 중 무엇인지 물었는데, 최종 질문은 계산하든 생략하든 0을 반환한다는 전제를 넣었다. 가상 사용자는 0이라고 답했고 공개 train 채점은 실제 곱을 기대해 실패했다.
- HumanEval/143: 1이 소수인지 질문. 표준적인 소수 정의와 예시로 판단 가능하지만 가상 사용자 평가는 QUALITY=3을 반환했다. 질문 품질 수치를 그대로 정답으로 삼기 어렵다.
- Mbpp/698과 Mbpp/753: 단순 판단과 속성 판단이 충돌을 제안했으나 최종 모델은 질문하지 않았고 둘 다 실패했다.

## 모델 사용

v1의 속성 추출과 판정은 일반 `env.llm` 호출로 실행됐으며, 실험 설정에는 별도 decision model이 없다. `env.decide`를 사용한 것은 PBT5·PBT5_1이다.

자세한 입력과 관점별 질문은 `V1_관점별_질문분석.md`, 모순 변형 원문은 `train100_모순변형_50문제.md`를 참고한다.
